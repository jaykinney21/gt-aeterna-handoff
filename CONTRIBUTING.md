# Continuing the project

For a quick start, download and unzip the repository and any model bundles you need. Open the repository folder in Codex, then use the current triage and specification matrix to choose a focused task.

For changes that Jay should review through GitHub, clone the repository with your own GitHub account, create a branch such as `codex/new-tripo-intake`, commit only the intended project files and open a pull request. A public repository is readable by everyone; write access must be granted separately or changes can be proposed through a fork.

Use `PROGRESS.md` to record what changed, the source revision, what was checked and what remains unresolved. Link the changed files and attach before/after views when visual decisions matter. Shared Space notes can link to the resulting commit or pull request.

Keep geometry and appearance exports together. Large native Blender, STL and GLB packages belong in release downloads; add their filename, revision, role and SHA-256 checksum to the model manifest. Do not overwrite the original incoming export or label a new concept as a released manufacturing file.

The original project computer's folder and Git preservation data remain separate. This repository starts a clean public history. Local changes on either Mac are visible to the other person only after deliberately sharing files or pushing a commit.
